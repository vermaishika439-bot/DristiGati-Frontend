# Backend integration notes

This document reflects the supplied `dristigati-backend` source and the frontend client in `src/api.js`, `src/useBackend.js`, and `src/socket.js`. The frontend expects the Flask service at the API origin configured in `VITE_API_BASE_URL` (default `http://127.0.0.1:5000`). JSON API responses use `{ "success": true, "data": ..., "timestamp": ... }`; endpoint failures remain visible and are not converted into healthy empty values.

## Read endpoints used

| Backend route                  | Frontend purpose                                                                                                                                                                                                                                                                                                     |
| ------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /api/health`              | Reachability and API status.                                                                                                                                                                                                                                                                                         |
| `GET /api/system/status`       | Aggregate camera, detection, rover, and mission status.                                                                                                                                                                                                                                                              |
| `GET /api/system/capabilities` | Simulation mode, camera/model availability, and hardware-test capability flags.                                                                                                                                                                                                                                      |
| `GET /api/rover/status`        | Rover mode, connection, sensor states, heartbeat, and active safety faults.                                                                                                                                                                                                                                          |
| `GET /api/mission/status`      | Current mission state, pause status, and any current detection included by the backend.                                                                                                                                                                                                                              |
| `GET /api/mission/history`     | Backend-recorded mission transitions. History is incomplete/process-local.                                                                                                                                                                                                                                           |
| `GET /api/camera/status`       | Backend camera configured/connected/streaming state, frame time/freshness, dimensions, and errors. The supplied version does **not** attest source identity.                                                                                                                                                         |
| `GET /api/camera/stream`       | Raw MJPEG route. The dashboard renders it only when the backend additionally reports a verified physical source and a recent frame; the supplied version does not provide that attestation, so the feed is withheld.                                                                                                 |
| `GET /api/camera/snapshot`     | JPEG snapshot route. The dashboard accepts a snapshot only when response headers attest `X-Camera-Source: physical-rover` and include a recent `X-Frame-Timestamp`. The supplied route does not emit these headers, so capture is withheld. For cross-origin use, the backend must expose both headers through CORS. |
| `GET /api/detections/current`  | Current detection event, if any.                                                                                                                                                                                                                                                                                     |
| `GET /api/detections/history`  | Detection records, if any; the supplied detection loop does not persist full history.                                                                                                                                                                                                                                |
| `GET /api/detections/config`   | Model configuration and weight availability. Weight presence does not prove successful inference.                                                                                                                                                                                                                    |
| `GET /api/obstacles/current`   | Current visual obstacle assessment, if returned.                                                                                                                                                                                                                                                                     |
| `GET /api/obstacles/history`   | Obstacle history, if returned. A visual warning does not itself stop the motors.                                                                                                                                                                                                                                     |
| `GET /api/obstacles/config`    | Obstacle-service configuration.                                                                                                                                                                                                                                                                                      |

There is no `GET /api/status`, `/api/video`, or `/api/video/annotated` route in the supplied backend. It also registers `/api/camera/annotated-stream`, but that handler returns a copy of the frame without drawing detection annotations. The frontend therefore disables “Annotated” mode and requests only the raw stream. Retained values from failed status endpoints are accompanied by a stale-data banner.

## Realtime events

Socket.IO is used only for events emitted by the supplied backend: `mission_state_changed`, `person_detected`, `person_event_acknowledged`, `person_cooldown_started`, `obstacle_candidate`, and `obstacle_warning_verified`. Mission status is reconciled through REST. Visual/person/obstacle event toasts are suppressed until both the physical rover and the physical-camera source/freshness are verified. The notification center and saved notification history are removed; brief action/safety toasts are not saved.

## Commands and safety gates

| Operator action              | Backend call                                                           | Frontend behavior                                                                                                                                                                                                                                                                                                                                                                                                      |
| ---------------------------- | ---------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Start search                 | `POST /api/mission/start`                                              | Locked unless `simulated_rover` is explicitly false, rover status confirms a connected `PHYSICAL` adapter, the camera reports trusted physical source and a fresh frame, safety sensors are `SAFE`, active safety faults are empty, the backend reports `hardware_tested: true`, and the API is reachable. The supplied backend lacks camera attestation and reports hardware untested, so this action remains locked. |
| Hold/stop                    | `POST /api/mission/stop`                                               | Sent only when the backend reports a connected physical rover and no operator/person-event/safety/emergency hold is already active. It is not shown as physically confirmed before a successful response.                                                                                                                                                                                                              |
| Resume search                | `POST /api/mission/resume`                                             | Locked unless physical mode/link, attested fresh camera source, backend hardware verification, sensor states, faults, and person-event acknowledgement requirements are satisfied. Resume never happens automatically after acknowledgement.                                                                                                                                                                           |
| Acknowledge person event     | `POST /api/detections/acknowledge` with `{ "event_id": "<event_id>" }` | Binds to the exact event ID; requires operator action and reports backend acceptance/failure. It does not resume the mission.                                                                                                                                                                                                                                                                                          |
| Turn around / return to base | No route/protocol exists                                               | Disabled and marked integration pending; no request is sent.                                                                                                                                                                                                                                                                                                                                                           |

There is no frontend command that bypasses backend checks, safety interlocks, controller watchdog, cliff sensing, or obstacle protection. UI build/test work does not issue movement commands. A post-command status refresh is awaited before the UI claims reconciliation.

## Physical-data and evidence handling

The dashboard fails closed: mission, rover, sensor, detection, obstacle, and history values are withheld unless capabilities explicitly report `simulated_rover: false` **and** rover status reports `mode: "PHYSICAL"` with `connected: true`. It does not treat a missing/failed capability response or a contradictory rover mode as physical confirmation.

Camera configuration and connectivity alone cannot prove that a URL is a physical rover camera. The supplied backend reports no trusted source identity, does not reject stale cached frames at snapshot time, and does not attach frame/source metadata to snapshot responses. Therefore the dashboard does not render camera imagery or enable capture with this backend version. To enable it safely, the backend must add an authenticated/controlled `source_verified: true` field to `/api/camera/status`, reject stale snapshots, return `X-Camera-Source: physical-rover` and a fresh `X-Frame-Timestamp` on snapshots, and expose those headers to the frontend origin through CORS. The current UI's evidence workflow is implemented but remains gated until that contract exists.

When available, saved screenshots are kept in this browser's IndexedDB with exact frame bytes and operator-entered event ID, title, and notes; no image is uploaded to the backend. A saved item opens immediately after a successful local save. Deleting it removes the local browser record.

## Known gaps in the supplied backend

- Default configuration is simulated; `hardware_tested` is hardcoded false. Therefore the frontend's Start and Resume actions remain locked with this backend until a backend version reports verified hardware after real safety testing.
- The service source does not implement Turn Around, Return to Base, localization, map/SLAM, coordinates, planned paths, persistent mission/detection history, or confirmed rescue-outcome reporting.
- The obstacle service reports candidate/verification data but does not issue a motor-stop command.
- The annotated stream route does not draw annotations; the UI disables that option.
- The camera service has no source provenance and can return a cached frame; no stream/snapshot is represented as physical evidence by the UI until attestation/freshness support is added.
- The backend does not provide frontend user authentication or durable notification storage; local login is a display/session convenience only.
- The archive contained no original logo file, so the frontend does not invent a substitute.
