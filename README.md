# DristiGati Operator Console

React + Vite frontend for the supplied DristiGati Flask/Socket.IO backend. The interface only renders data returned by configured backend endpoints. It does not create sample detections, rover positions, map routes, rescue outcomes, or synthetic camera frames.

## Requirements

- Node.js 18 or newer and npm.
- Python 3.11 for the supplied backend.
- The `dristigati-backend` folder from the supplied backend archive, extracted separately.
- A configured backend and (for physical telemetry) the rover's actual camera/controller integration.

## Run in VS Code on Windows

1. Extract this frontend ZIP to a folder, then open that folder in VS Code (`File > Open Folder`). Open a second VS Code window for the extracted backend folder.
2. In a PowerShell terminal in the backend folder, create and activate a virtual environment, then install its dependencies:

   ```powershell
   py -3.11 -m venv .venv
   .\.venv\Scripts\Activate.ps1
   python -m pip install -r requirements.txt
   Copy-Item .env.example .env
   ```

   Keep the backend's simulated-rover setting enabled during development. Set its camera URL only to the real rover camera stream. If the backend's CORS allow-list is restricted, allow the frontend origin `http://localhost:5173`.

3. Start the backend with `python app.py` (the supplied Flask service listens on port `5000` by default). Keep this terminal open. Do not run `start`, `resume`, or other movement commands against an attached physical rover during setup or UI testing.
4. In a second PowerShell terminal in the frontend folder:

   ```powershell
   Copy-Item .env.example .env
   npm ci
   npm run dev
   ```

5. Open the local Vite URL printed in the terminal (normally `http://localhost:5173`). Enter any local email/username and a non-empty password, then open the console; the credentials are not verified and the password is discarded. This is a local UI session only, not backend authentication.

The default API origin is `http://127.0.0.1:5000`. To use another host/port, set `VITE_API_BASE_URL` in the frontend `.env`, or update **Settings → Backend API**. The Settings value is saved only in this browser. Do not put passwords or private credentials in the frontend environment file. If a browser blocks cross-origin requests, configure the backend's CORS allow-list for the exact frontend origin; do not disable browser security.

## Commands

```bash
npm run dev      # Local development server
npm test         # Utility tests
npm run build    # Production static build in dist/
npm run preview  # Preview the built files locally
```

## Safety and known integration limits

- The supplied backend defaults to simulated-rover mode and reports `hardware_tested: false`. Physical mission, rover, sensor, and history data stay withheld unless capabilities explicitly disable simulation and rover status confirms a connected `PHYSICAL` adapter. Camera-derived detections/history and camera imagery also require backend attestation of a physical camera source and a fresh frame. Start/resume stay locked unless all required camera, safety, and hardware-verification conditions pass. The frontend does not loosen backend preconditions.
- STOP is exposed only when a physical link is reported and a duplicate hold is not already active. The dashboard uses only documented `start`, `stop`, `resume`, and event-acknowledgement routes. “Turn Around” and “Return to Base” remain disabled because the backend has no corresponding route or rover protocol.
- A physical status response is not proof that hardware has been tested. The camera service does not attest source identity and its snapshot route may return a cached frame, so the dashboard withholds camera imagery and evidence capture until the backend adds physical-source and fresh-frame attestation. Do not connect an unverified controller and infer that software interlocks are a substitute for hardware safety systems.
- Detection and mission histories in the supplied backend are incomplete/in-memory. Missing history, mapping/localization, mission IDs, durations, and confirmed rescue outcomes remain unavailable rather than being generated by the UI.
- Operator sign-in, theme, and API URL are browser-local conveniences, not access control. The login email/name are stored locally in session storage or local storage (when Remember is selected); passwords are never stored or sent to the backend. The notification center and saved notification history are removed; brief action/safety toasts are not saved. Screenshots are stored in this browser's IndexedDB; they are not uploaded to the backend. Removing browser data can erase them.
- The redesign archive did not include the DristiGati logo asset. The interface uses a text wordmark until the actual logo is supplied; no replacement logo is fabricated.

For endpoint-to-field details, Socket.IO events, physical-data gating, and backend limitations, see [BACKEND_INTEGRATION.md](./BACKEND_INTEGRATION.md).
